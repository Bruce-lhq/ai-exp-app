# AI 实验平台

第一版设计已确认，当前实现已完成本地首版交付，正在进入真实远端实验前的验收阶段。

完整第一版设计与验收场景见 [设计文档](docs/superpowers/specs/2026-09-28-ai-experiment-platform-design.md)，执行步骤见 [实施总计划](docs/superpowers/plans/2026-09-28-ai-experiment-platform.md)及其中链接的五份分阶段计划。下文为需求摘要；详细交互和数据规则以已确认设计文档为准。

## 已确认的第一版范围

- 面向个人使用，以现有 SSH GPU 上的 launcher 实验为首个支持项目。
- 通过 localhost 网页操作，提供可放入 macOS 程序坞的应用入口。
- 代码在外部编辑和同步；平台选择远端已有目录、分支或版本，配置并运行实验。
- 启动或加入队列时固定代码快照，实验从独立快照运行，原目录的后续修改不影响已排队实验。支持普通目录；Git 项目额外记录分支、提交及未提交修改。数据集和实验输出不随代码复制。

## 参数组

- 支持多套可自由编辑、命名的参数组，例如 `wonn`、`s1llt`、`wonn-ca`。
- 首次接入项目时，从源码默认值创建初始参数组；该组也可自由编辑。
- 不设置固定的默认参数组。程序／应用重启后，参数编辑区展示上次启动实验实际提交的参数快照，而不是重新加载某个已保存参数组；即使来源参数组已改名、修改或删除，恢复的参数也不受影响。没有运行记录时使用源码默认值。
- 每次实验独立保存实际使用的参数，后续编辑参数组不改变历史实验记录。
- 参数组按项目（常用区中的远端代码目录）独立保存，各项目分别记录上次启动实验实际提交的参数快照；同一项目切换代码版本时保留参数组。支持跨项目复制，并按目标源码检查兼容性。
- 当前参数编辑区与已保存参数组独立。加载参数组后修改的是当前草稿，不自动覆盖原组；运行实验也不隐式保存或更新参数组。
- 同一编辑界面提供独立操作：启动实验／加入队列（提交当前参数快照）、保存到当前参数组（明确更新已有组）、另存为新参数组（输入名称创建）、还原源码默认值（仅重置编辑区）、载入参数组（将应用中已有参数组复制到编辑区）。
- 参数组导入分为两步独立操作：“从 JSON 导入参数组”经目标项目源码兼容性校验及必要修正后保存到应用的参数组列表，不自动覆盖编辑区；“载入参数组”从应用已有参数组复制参数到编辑区，不改动已保存组。
- 未提交运行的临时编辑不替代“上次运行参数”这一重启展示依据；已有参数组仅在明确保存时更新。
- 支持从历史实验实际参数载入编辑区、仅查看相对源码默认值或其他实验的差异参数。参数支持显示备注及恢复原名、拖动排序、标星置顶、自定义分类标签。
- 参数组支持导出 Markdown 表格（类型、参数名称、默认值）；枚举字符串使用下拉框，数字／字符串混合参数允许选字符串或输入数字。
- 支持 JSON 导入、导出。导入、跨项目复制或切换代码版本时，按所选源码的参数定义检查：未知参数忽略且不传给训练程序，并警告；缺失参数若有源码默认值则补入并警告，若无默认值且为必填则要求补填。
- 参数类型错误、选项失效或违反已知约束时，不允许提交该值；导入中的同类错误须手动修正，不自动回退默认值。未解决时禁止保存为有效参数组或启动实验。
- 数值输入支持大小写不敏感的 K/M/B，分别转换为千／百万／十亿，并按目标参数类型校验。
- 界面展示自动修复清单；保存及导出的 JSON 使用校验通过、自动修复后的有效参数，不保留被忽略的未知参数。历史实验参数记录不随兼容性修复改变。

## GPU 分配与队列

- 用户只指定 GPU 卡数，卡数纳入参数组，并随 JSON 导入／导出；它属于平台运行配置，不作为普通模型参数直接传入训练程序。
- 启动时从可用 GPU 中优先分配编号最小的卡，实际卡号写入实验记录，不要求编号连续。
- 队列严格按顺序调度，支持拖动调整尚未启动的任务。队首资源不足时不得跳过；队首启动后再检查下一项，资源足够时可并发运行多个实验。
- 只有拖动能改变等待顺序。“启动实验”不会绕过已有等待任务，资源不足或队列不可立即调度时提示并提供入队操作，不静默入队；“加入队列”固定追加至队尾。
- 启动前展示实验名称、代码版本、GPU 卡数和改动参数摘要，不增加强制确认步骤。GPU 分配同时检查实际进程与平台预留，不占用平台外实验所用设备。
- 实验与队列在远端运行，关闭网页、Mac 休眠或本地 SSH 断线不影响远端执行；重新连接后同步状态。
- 实验异常退出（如 OOM、程序报错）时暂停后续队列调度，已运行的其他实验继续；用户检查后手动恢复，不自动恢复。SSH 断线本身不判定为实验失败。
- 实验失败时提供应用内持久提醒和 macOS 系统通知，说明失败实验、错误摘要及队列暂停状态，并提供查看日志入口。系统通知依赖用户授予通知权限及本地通知组件可用；Mac 离线或休眠期间发生的失败在重连同步后补提醒，不承诺即时送达。

## 停止、续跑与归档

- 第一版仅支持完整训练状态续跑：恢复模型、优化器（含动量状态）、学习率进度、AMP scaler、训练步数／token 进度、各 rank 随机数状态及数据采样位置；沿用原代码快照、训练配置与 GPU 卡数。不提供仅加载权重、改参数或换代码后的续跑。
- 续跑前核查完整 checkpoint 和运行条件；无法满足完整状态恢复时禁止续跑，不静默降级。恢复状态不等于在非确定性算子或不同硬件环境下保证逐位一致。
- 停止实验必须确认；第一版停止时不要求训练程序额外保存 checkpoint，续跑使用已有的最近完整 checkpoint。当前 launcher 默认保存间隔为 50M tokens，用户接受回退到最近保存点。
- 用户主动停止实验后默认继续队列调度，停止确认框提供“同时暂停队列”选项；待目标进程退出、资源释放后才能分配其 GPU。主动停止不作为异常失败触发队列暂停。
- 可查看所有已停止实验。归档仅在界面隐藏，不移动或删除训练文件；可取消归档恢复显示，此操作不等于续跑。
- 永久删除须单独确认，并明确列出目标实验和实际删除范围；运行中的实验不得直接永久删除。当前仅记录产品要求，不执行任何实验删除。

### 2026-09-28 源码只读核查

- 已检查云端 `bump_launcher_5_0`、`bump_launcher_6_0`、`s1llt1_0` 的相关源码；5.0 与 s1llt 的 `train.py`、`utils.py` 哈希与本地镜像一致。
- 完整 checkpoint 保存优化器、scaler、每个 rank 的 RNG／采样位置等；5.0 的恢复路径加载这些状态，并校验影响训练轨迹的参数、数据 manifest 和 world size。学习率根据恢复后的 token 进度及原调度参数计算。
- `latest.pt` 不仅在 eval 后更新：定期保存、训练指标最佳值更新或验证指标最佳值更新均可触发；所查默认 eval 与 save 间隔均为 50M tokens。实际续跑点应读取 checkpoint 的进度，不能从最后一条 eval 日志推断。
- 所查训练入口未发现停止信号触发保存退出的处理。完整续跑已有支持，停止时主动保存需要训练端配合，已按用户决定移至 Future work；本次未修改远端代码，也未启动／停止实验或做续跑实测。

## 历史实验、缓存与导出

- 不自动扫描或导入已有实验。用户从本地或云端手动选择实验目录导入，可重命名，随后进入可多选勾选的历史下拉框，用于曲线对比和表格导出。
- 实验支持备注、自定义标签及标签筛选，备注可作为表格列。重命名改变显示及导出名称，不改变远端运行目录。
- 平台自身启动的实验完成、主动停止或失败后，自动进入历史并缓存日志、指标和参数；应用运行且连接正常时自动同步。此规则不扩展为扫描其他既有实验。
- 从历史下拉框删除仅移除历史条目，不删除源文件或本地缓存；以后需要时手动重新导入。必须记录移除状态，防止下次同步再次自动加入。此操作与实验归档、取消归档及永久删除文件区分。
- 云端导入的实验默认缓存至本地 `gpu_downloads`，运行中的实验同步已有内容，结束后补齐最终内容；缓存可离线查看、导出，源目录可用时支持刷新。
- 缓存／导出沿用 `ssh gpu download` 的每实验一目录形式，使用用户重命名后的实验名称作为实验目录名；若导出打包文件，包名也使用该名称。目录内保留 `args.json`、`metrics.jsonl`、日志等标准文件名。默认不下载大型 checkpoint。
- 支持导出历史及运行中的实验已有内容；自动同步与导出复用同一套文件获取能力，不另设重复的“下载实验”流程。

- 同一实验持续更新同一份本地缓存，停止／完成后以远端最终文件为准，续跑后继续更新；不为每次同步生成新目录，不因不同实验重名而相互覆盖。文件先下载到临时位置，完整获取后再替换已有缓存。

### 断线补同步

- 本地持久保存平台管理的实验标识、远端路径、历史移除标记及同步进度。应用重启或网络恢复时核对这些实验的远端状态，补导入和下载期间结束的实验，不自动扫描其他目录。
- 训练状态与同步状态分别展示；下载中断可重试，未完成的同步不能标为完成，重复重连不创建重复历史条目。
- 远端进程／节点不可达时状态为连接异常或待核实，不能直接判为实验失败。若远端文件在同步前已被删除或存储不可恢复，则只能保留已缓存内容并提示缺失。

## 曲线与历史对比

- 默认绘制 `val_ppl` 对训练 tokens 的曲线，支持选择其他指标，横轴可切换 step 或实际训练耗时。
- 历史下拉框支持多选叠加对比，允许比较来自不同项目的实验。
- 某个已勾选实验缺少所选指标时，显示警告并仅跳过该实验在当前图中的曲线；不阻止其他实验绘图，不取消勾选、不移除历史条目，也不将缺失数据填零。
- 切换指标时重新判断各实验的数据可用性；此前缺失指标的实验若具备新指标，则自动参与绘图，无须重新勾选。
- 图表调整满意后可下载到本地，默认格式为 PNG；第一版不增加已保存图表库。
- 支持标题、坐标轴名称与范围、线性／对数坐标、曲线颜色、图例和 PNG 清晰度设置；默认不平滑。

## Markdown 实验表格

- 从已选历史实验生成表格，支持勾选所需列；默认模板包含超参数、指标统计、指标相对 baseline 的差值、参数量、相对 baseline 参数量百分比五类内容。
- 各种 metrics 支持 max／min／final 统计；默认指标列为 `val_ppl best(min)` 与 `val_ppl final`。此处 final 表示实验末次有效指标记录，不能将历史最优值冒充 final。
- 手动停止实验的指标单元格末尾加 `@…B`，表示手动停止的训练进度；停止进度与指标实际采样进度应区分，缺失或不可核实的数据不得伪造。
- baseline 从历史实验中选择。每个指标统计列右侧紧挨对应的 `△ vs baseline` 列，计算实验值减去 baseline 同指标同统计口径的值，保留正负号；baseline 自身显示 `-`，缺失数据也显示 `-` 并说明原因。
- 展示参数量及相对 baseline 的参数量增减百分比，计算为 `(当前参数量 / baseline 参数量 - 1) × 100%`，例如 `+20%`、`-15%`；baseline 参数量缺失或为零时不计算。
- 默认表格模板可编辑；支持新建、命名并持久保存自定义模板。模板用于复用列选择、指标统计方式和列顺序，指标差值列始终紧挨对应指标右侧。
- 模板中每列的列头均可重命名，包括超参数、指标、差值和参数量列。自定义列头仅影响显示及导出标题，不改变底层字段、统计口径、计算结果或单元格数据；列头名称随模板保存，不作为数据绑定标识。
- 实验表格支持下载为 `.md` 文件及一键复制 Markdown。
- 每列可设置小数位、科学计数法及 K/M/B 显示；计算使用原始精度，不使用舍入后的屏幕值。

## 页面工作区

1. 配置实验：选择常用项目、远端目录及代码版本／分支，编辑参数组，启动或加入队列。
2. 运行监控：查看 GPU、运行实验、队列、日志与实时曲线，停止或续跑实验。
3. 历史管理：本地／云端导入、重命名、归档／恢复、从历史移除、实验文件导出及同步状态。
4. 画图与列表：勾选历史实验，调整图表；选择 baseline、编辑表格模板，下载图表或下载／复制 Markdown 表格。此处不是已保存图表的管理列表。

## Future work

- 点击停止后，协调训练程序保存完整 checkpoint 再退出；按项目能力支持，不能假设任意项目都提供 checkpoint。
- 显示最近可恢复的位置及停止可能损失的训练进度；按项目 checkpoint 能力支持。
- 支持通过平台将本地代码修改同步到远端，再运行实验；第一版不包含此功能。
- 多 seed／参数扫描：预览组合与任务数量后批量加入队列。
- 多 seed 统计：配置分组、均值与波动范围曲线、均值 ± 标准差表格。
- 本地配置备份／恢复：参数组、模板、显示备注及历史索引，不包含 SSH 密码或大型 checkpoint。
- 第二版面向 GitHub 开源发布，推广至其他用户和实验项目。
